# パーティションとインストール

[ホームへ戻る](../README.ja.md) · [非公開コンポーネントの取得とビルド](BUILDING.ja.md)

[简体中文](INSTALL.md) · [繁體中文](INSTALL.zh-TW.md) · [English](INSTALL.en.md) · **日本語**

このガイドは、クリーンな Walkman One ファームウェアを実行している Sony NW-ZX300A 向けです。WalkDroid はパソコンから Fastboot で boot イメージを一時的に RAM に読み込み、純正 boot には書き込みません。Android の system と data は内蔵音楽パーティションの後部に配置します。再起動すると純正ファームウェアが起動します。

**初回インストールでは内蔵音楽 FAT ファイルシステムを再作成します。音楽と残しておきたいファイルをすべてパソコンにコピーし、さらに音楽パーティション全体をバックアップしてください。** クリーンな Walkman One では FAT が通常、音楽パーティションの大部分を占めています。その後部に Android イメージを直接書き込まないでください。ファイルがないように見えるセクターも FAT ファイルシステムに属している可能性があります。バックアップと復元手段を用意するまでは書き込まないでください。microSD と純正の重要パーティションはこのインストールの対象外です。

## 配置

外側のパーティションは `/dev/block/mmcblk0p29` のままです。外側のパーティションの追加やパーティションテーブルの変更は行いません。以下のオフセットはすべて p29 の先頭からの値です。

| 用途 | 開始バイト | 終了バイト（含まない） | サイズ |
| --- | ---: | ---: | ---: |
| 音楽 FAT32 | 0 | 4,294,967,296 | 4 GiB |
| Android system ext4 | 4,294,967,296 | 6,442,450,944 | 2 GiB |
| Android data ext4 | 6,442,450,944 | 13,291,225,088 | 6,848,774,144 バイト |

システムは後ろの 2 つの範囲を device-mapper でマッピングします。これらは FAT 内のファイルではありません。USB LUN 全体のサイズでフォーマットしないでください。後部を覆うように FAT を拡張したり、音楽ディスク全体を再作成する純正フォーマットを使ったりしないでください。この配置は上記容量の ZX300A 向けです。他の端末や異なる配置には、それぞれインストール方法を設計する必要があります。

## 1. バックアップ

p29 の生データを保存するためにパソコンに 13.3 GB 以上の空き容量を用意し、音楽ファイルの完全なコピーも別に保存します。まずプレーヤーの音楽ディスクへの読み書きを止め、パソコン側でアンマウントし、確認済みの純正 ADB 接続を維持してください。稼働中のパーティションのバックアップは、端末全体のオフライン原子的スナップショットではありません。

[ビルドガイド](BUILDING.ja.md)で確認した `SERIAL`、`CID`、`PRIVATE` を使います。

```sh
python3 "$REPO/tools/install_walkdroid.py" backup --serial "$SERIAL" --cid "$CID" \
  --backup "$PRIVATE/p29-before.img"
```

読み取るのは p29 のみです。eMMC の残りのパーティション、RPMB、取り出せない端末鍵、microSD は含みません。バックアップは 13,291,225,088 バイトになるはずです。音楽領域への書き込みがない状態で、端末の元データとパソコン側のコピーの SHA-256 をそれぞれ計算し、一致を確認できます。これはバックアップの確認であり、システムや以後のビルドの要件にはなりません。

```sh
adb -s "$SERIAL" shell /sbin/busybox sha256sum /dev/block/mmcblk0p29
sha256sum "$PRIVATE/p29-before.img"
```

通常のファイルコピーで保存した音楽も残し、生バックアップはパソコンに保管してください。ファイル一覧やパーティションヘッダーだけのバックアップは、音楽ファイルの内容のバックアップではありません。

## 2. 準備と書き込み

音楽ボリュームがパソコン側でもプレーヤー側でもマウントまたは使用されていないことを確認します。以下のコマンドは空の 4 GiB FAT32 イメージを作成し、上表の指定範囲に書き込みます。初回インストールで音楽 FAT を再作成した後、通常のファイル転送で必要な音楽をプレーヤーに戻せます。新しい音楽ボリュームの容量は 4 GiB です。

```sh
truncate -s 4294967296 "$PRIVATE/music-fat.img"
mkfs.vfat -F 32 -n WALKMAN "$PRIVATE/music-fat.img"
python3 "$REPO/tools/install_walkdroid.py" write --serial "$SERIAL" --cid "$CID" \
  --music-image "$PRIVATE/music-fat.img" \
  --system-image "$PRIVATE/images/system.img" \
  --data-image "$PRIVATE/images/data.img"
```

書き込みツールは明示的に指定され、身元を確認したプレーヤーだけを対象とし、固定範囲内に分割して書き込みます。中断時はその範囲が一部しか書き込まれていない可能性があります。パソコン側のバックアップを保持して中断への対処を優先し、別の端末を選ばないでください。すでにこの配置を使っていて Android のみを更新する場合は、`--music-image` を省略し system または data だけを書き込めます。data を再作成すると既存の Android データは消去されます。

## 3. RAM 起動

起動前に、今回組み立てた boot イメージのロード配置を確認します。

```sh
python3 "$REPO/tools/ramboot_layout.py" "$PRIVATE/images/boot.img"
```

これは RAM 起動に必要なメモリ配置を確認し、DRAM、LK の予約領域、コンポーネントの境界を含みます。端末には書き込みません。確認後、先ほど確認した同じプレーヤーを Fastboot に切り替え、同じ物理 USB ポートを維持します。Fastboot で列挙された USB シリアルと物理ポートが同じであることを確認し、Fastboot シリアルを明示して実行します。

```sh
adb -s "$SERIAL" reboot bootloader
fastboot devices -l
export FASTBOOT_SERIAL='ここに同じプレーヤーの Fastboot USB シリアルを入力'
fastboot -s "$FASTBOOT_SERIAL" boot "$PRIVATE/images/boot.img"
```

この端末の Fastboot は、使用可能な `getvar serialno` や eMMC CID を提供しない場合があります。そのために別の端末を選ばないでください。モード切り替えが連続していない場合、または USB シリアルや物理ポートが一致しない場合は停止してください。純正パーティションからバックアップした `stock-boot.img` に対して `fastboot boot` を実行しないでください。ロードアドレスがこの RAM 起動方式に適していません。

新しく作成した data の Walkman 音量は既定で 60 / 120 です。音声設定で調整できます。

通常の再起動では Walkman One に戻り、実験領域は p29 後部に残ります。音楽ボリュームの配置を変更したり、その領域を取り戻したりする場合は、必要な音楽と Android データを先にバックアップし、別途その作業を計画してください。boot イメージを交換しても音楽パーティションの配置は自動では復元されません。
